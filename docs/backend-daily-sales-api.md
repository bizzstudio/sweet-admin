# בקאנד: מכירות לפי מוצר לפי יום (דשבורד)

הדשבורד שולח בקשה ל־`GET /orders` עם הפרמטרים הבאים כדי לקבל הזמנות לפי תאריך:

## פרמטרים שנשלחים

| פרמטר   | דוגמה                          | הסבר |
|----------|----------------------------------|------|
| `startDate` | `2026-03-12T00:00:00.000+02:00` | תחילת היום (ISO) |
| `endDate`   | `2026-03-12T23:59:59.999+02:00` | סוף היום (ISO)   |
| `page`      | `1`                             | דף תוצאות       |
| `limit`     | `1000`                          | מקסימום הזמנות לתשובה |

## מה הבקאנד צריך לעשות

1. **סינון לפי תאריך**  
   להחזיר רק הזמנות ש־`createdAt` (או השדה שבו שומרים תאריך ההזמנה) נמצא **בטווח** שבין `startDate` ל־`endDate` (כולל).

2. **מבנה התשובה**  
   כמו בשאר קריאות ל־`/orders`: אובייקט עם מערך `orders`, וכל הזמנה כוללת **`cart`** מלא (כל פריט עם `title`, `quantity`, `id` או `_id`).  
   בלי `cart` המלא, הפרונט לא יכול לחשב "כמה נקנה מכל מוצר" ליום הנבחר.

3. **פורמט תאריכים**  
   הפרונט שולח תאריכים בפורמט **ISO 8601** (תחילת/סוף יום).  
   בבקאנד להשוות לפי timestamp (למשל: `createdAt >= startDate && createdAt <= endDate` אחרי המרה ל־Date/זמן).

## דוגמה ללוגיקה בבקאנד (תלוי ב־ORM/DB)

```js
// דוגמה: MongoDB/Mongoose
const start = new Date(req.query.startDate);
const end = new Date(req.query.endDate);
const orders = await Order.find({
  createdAt: { $gte: start, $lte: end }
}).populate('cart'); // או להחזיר cart מוטמע
```

אם ה־API כבר מסנן לפי `startDate`/`endDate` אבל בפורמט אחר (למשל רק YYYY-MM-DD), צריך לוודא שההשוואה ל־`createdAt` מכסה את **כל היום** (מחצות עד 23:59:59).
